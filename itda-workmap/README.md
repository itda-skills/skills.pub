# itda-workmap

> **🟢 처음이세요? → [GUIDE.md](GUIDE.md) 한 장만 보세요.** 코드 몰라도 됩니다. "내 업무 구조화해줘"라고 적으면 인터뷰가 시작됩니다.

**업무 구조화 스킬팩** — AI에게 일을 통째로 던지고 나온 걸 그대로 넘기는 **의존**을,
방향과 기준을 알고 맡긴 뒤 검증하는 **위임**으로 바꿉니다. AI 활용의 총량은
`사용자 능력 × 모델 성능`의 곱이라, 내 일을 구조로 그리는 앞자리가 0이면 모델이
좋아져도 결과는 0에 가깝습니다. 이 팩은 그 앞자리를 만드는 도구를 담습니다.

## 스킬

| 스킬 | 막막함의 종류 | 하는 일 |
|------|--------------|---------|
| `work-redesign` (업무 구조화) | "뭘 AI한테 맡기고 뭘 내가 해야 하지?" | 프로젝트 1개를 태스크→행동 단위로 쪼개고 가치×AI개입 4분면으로 매핑해, 위임 계획과 상시 컨텍스트 문서(업무 지도)를 만든다 |
| `time-audit` (시간 감사) | "뭐가 오래 걸리는지 모르겠다" | 캘린더 실적(MCP 커넥터·itda-calendar·파일)을 정규화해 카테고리·난이도별 시간, 주별 추이, 병목 후보를 결정론 스크립트로 집계한다 — 4분면의 실측 근거 |
| `stakeholder-map` (협업 지도) | "나 때문에 일이 막힌다" | 이해관계자별 요청·받을 것·**선행 전달물(제약 조건)**·소통과 요청 순서를 문서로 굳힌다 — "알아서 잘"은 게이트가 반려 |

### 산출물 — 업무 지도 3종

```
work-map.md          # 태스크 인벤토리 · 4분면 매핑 · 다음 행동
project-context.md   # 프로젝트 맥락 (목표·제약·용어)
stakeholders/*.md    # 이해관계자별 요청·선행 전달할 제약 조건
```

구조 게이트(`check_work_map.py`)가 전부-자동화 답안(지킬 것 0건)·뭉텅이(태스크 1개)·
일반론(사용자 맥락 미재등장)을 기계적으로 반려합니다.

## 인접 스킬과의 파이프라인

```
time-audit(실측) ─▶ work-redesign(업무 지도) ─▶ stakeholder-map(협업 지도)
                       ├─ 자동화할 것   → itda-work:work-find → itda-coach:miniskill-forge
                       ├─ 위임 1건 실행 → itda-work:task-brief ◀─ 선행 전달물 복사
                       └─ 오늘 첫 조각  → itda-coach:hour-slice
```

time-audit 는 work-map.md 의 태스크를 분류 축으로 쓰고 집계 결과를 4분면의 실측 근거로
되돌려 주며(지도 ↔ 실측 왕복), stakeholder-map 은 work-redesign 의 관계자 스텁을 심화해
선행 전달물을 task-brief 의 입력으로 잇는다. 각 스킬은 단독 호출도 된다.

각 스킬이 없어도 work-redesign 은 단독 동작합니다(핸드오프 단계는 대화로 대체).

## 설계 원칙

- **일반론은 반려** — "AI에게 업무 구조화해줘"의 함정(일반론 답안)을 구조 게이트로 차단한다. 사용자 고유 맥락이 본문에 재등장해야 통과.
- **왼쪽 두 칸부터** — 자동화 목록이 아니라 "인간이 지킬 것"과 "일부러 안 할 것"을 먼저 정한다.
- **검증 없는 위임은 의존** — 증강 항목마다 결과 판정 방법을 요구한다.
