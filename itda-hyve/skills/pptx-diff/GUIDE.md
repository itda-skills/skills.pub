---
title: "pptx-diff 상세 가이드"
---

PPTX 발표자료 두 버전의 차이를 슬라이드·도형·텍스트 단위로 비교해 한국어 변경 요약으로 정리합니다.
**Claude에게 말로 부탁하면 됩니다** — "이 pptx 두 버전 비교해줘", "덱 뭐가 바뀌었어?"처럼요.

덱을 새로 **만드는** 일은 `itda-work:pptx-design`이 맡습니다. 이 스킬은 오직 **두 버전 사이에 무엇이 바뀌었는가**만 다루며, 파일을 고치지 않습니다.

---

## 빠른 시작

```
/pptx-diff 이 pptx 두 버전 비교해줘
/pptx-diff 덱 뭐가 바뀌었어?
/pptx-diff 발표자료 개정본 리뷰해줘
/pptx-diff 슬라이드 변경 내역 정리해줘
```

비교할 두 파일(또는 비교할 시점)을 알려주면, 스킬이 슬라이드별 추가·삭제·수정·이동을 집계해 한국어로 요약해 줍니다.

---

## 사전 준비

이 스킬은 hyve의 문서 비교 기능을 호출하므로, 아래 네 가지가 준비되어 있어야 합니다.

| 준비 항목 | 내용 |
|------|------|
| hyve 설치·가동 | <https://hyve.pub> 에서 설치한 뒤 실행해 둡니다. |
| `office` 프리셋 등록 | hyve 설정의 MCP 탭에서 `office` 프리셋을 등록합니다. 유저향 정본은 이 설정 화면입니다. |
| 실험 기능 켜기 | 문서 읽기 기능은 실험(experimental) 도메인이라, hyve 설정에서 실험 도메인을 켜지 않으면 호출이 거부됩니다. |
| 파일 접근 루트 등록 | 비교할 `.pptx` 가 있는 폴더가 hyve 파일 접근 루트에 등록돼 있어야 합니다. |

준비가 빠져 있으면 Claude가 아래 증상을 그대로 알려주고 멈춥니다. 다른 도구로 갈아타 비슷한 결과를 만들어내지 않습니다.

- **실험 기능이 꺼져 있음** (`experimental_domain_disabled`) — hyve 설정에서 실험 도메인을 켜고 다시 요청하세요.
- **파일 접근 루트 미등록** — 해당 폴더를 접근 루트에 추가하라는 안내가 함께 나옵니다. 데스크톱 알림에서 승인하는 흐름입니다.

## 활용 시나리오

### 재생성한 덱의 회귀 확인

`itda-work:pptx-design` 등으로 덱을 다시 만든 뒤, 의도한 것만 바뀌었는지 확인합니다. 의도한 변경과 의도치 않은 변경을 갈라서 보고합니다.

```
/pptx-diff 새로 만든 덱이 예전 거랑 뭐가 달라?
/pptx-diff 새 덱을 이전 덱이랑 비교해서 의도한 것만 바뀌었는지 봐줘
```

### 받은 개정본 리뷰

동료가 고쳐 보낸 수정본을 원본과 비교해, 어디를 손댔는지 목록으로 만듭니다. 수정된 슬라이드가 있으면 그 슬라이드의 문구 변경을 "'기존 문구' → '바뀐 문구'" 형태로 인용해 줍니다.

```
/pptx-diff 받은 수정본에서 뭐 고쳤는지 확인해줘
/pptx-diff 제안서 v2를 v1이랑 비교해서 바뀐 문구 정리해줘
```

### 버전 관리 중인 덱의 커밋 간 리뷰

덱이 git 저장소에 들어 있다면 커밋 시점끼리, 또는 커밋과 지금 저장된 파일을 비교할 수 있습니다.

```
/pptx-diff 이 덱 직전 커밋이랑 뭐가 달라졌는지 정리해줘
/pptx-diff 커밋 안 한 내 수정분이 뭐지?
```

## 출력 옵션

무엇과 비교할지는 두 방식 중 하나로 정해집니다. 두 방식은 함께 쓸 수 없으니, 손에 파일 두 개가 있으면 파일 비교를, 덱이 버전 관리되고 있으면 커밋 비교를 요청하세요.

| 비교 방식 | 설명 | 자연어 예시 |
|------|------|-------------|
| 파일 비교 | 서로 다른 두 `.pptx` 파일을 비교합니다. 버전 관리 중이 아니어도 됩니다. | "이 두 파일 비교해줘" |
| 커밋 비교 | 같은 파일의 리비전 사이, 또는 특정 커밋과 지금 저장된 파일을 비교합니다. | "직전 커밋이랑 비교해줘" |

보고 상세 수준도 두 단계입니다.

| 상세 수준 | 담기는 내용 | 사용 시점 |
|------|------|-----------|
| 요약 (기본) | 슬라이드별 추가·삭제·수정·이동 상태, 도형의 이름·종류·변경 축, 전체 집계 | 무엇이 바뀌었는지 규모부터 볼 때 |
| 상세 | 위에 더해 단어 단위 문구 변경, 표 셀 변경, 도형 좌표 | 어느 문구가 어떻게 바뀌었는지 원문까지 볼 때 |

기본은 요약입니다. 대형 덱을 처음부터 상세로 받으면 결과가 너무 커져 읽기 어려우므로, 문구 원문이 필요할 때 "그 슬라이드 문구까지 자세히 보여줘"라고 이어서 요청하세요.

## 보고 내용 읽는 법

비교 결과에는 아래 조건에 해당하는 경고가 함께 붙습니다. 경고가 보이면 그 전제를 감안해 읽으세요.

- **"위치 기반 비교" 경고** — 슬라이드 고유 ID가 이어지지 않아 위치 순서로 짝을 맞췄다는 뜻입니다. 덱을 새로 만들어 낸 경우의 전형이며, 이때는 **이동 여부를 판정할 수 없습니다**. 슬라이드 순서가 바뀌었다면 이동이 아니라 수정이나 추가로 잡힙니다.
- **테마 변경 경고** — 테마·슬라이드 마스터·레이아웃이 바뀌었다는 뜻입니다. 글꼴·배색·머리말처럼 **슬라이드 목록에는 안 잡히는 전체 디자인 변경**이 포함돼 있을 수 있습니다.
- **수정됐다는데 바뀐 도형이 없음** — 파일 내부 재저장 차이입니다. 표시상으로는 달라 보이지 않을 수 있으며, 실제 편집으로 단정하지 않습니다.
- **슬라이드 크기 변경** — 화면 비율 자체가 바뀐 경우(예: 4:3에서 16:9)로, 개별 슬라이드 변경보다 먼저 알려줍니다.
- **변경 축 다섯 가지** — 위치 이동 · 크기 변경 · 서식 · 문구 · 표 셀. 서식 판정은 좌표와 텍스트를 제외한 비교라, **도형 이름만 바꾼 변경은 의도적으로 잡지 않습니다**.

위치·크기는 내부적으로 EMU라는 아주 작은 단위로 다뤄지므로, 보고에는 인치나 cm로 환산하거나 "약간 이동" 같은 정성 표현으로 옮겨 적습니다.

## 팁

- **요약부터 보고 필요할 때만 파고들기**: 처음에는 규모(몇 장이 추가·삭제·수정됐는지)만 확인하고, 문구가 궁금한 슬라이드만 골라 자세히 요청하는 편이 읽기 편합니다.
- **바뀐 게 없으면 없다고 말해 줍니다**: 집계가 전부 0이면 "구조적 변경 없음"으로 보고하고 끝냅니다. 없는 변경을 지어내지 않습니다.
- **슬라이드 번호는 1번부터**: 내부 인덱스는 0부터지만, 사용자에게는 "3번 슬라이드"처럼 1부터 세어 말해 줍니다.
- **재생성한 덱은 위치 기반 비교가 기본값이라고 생각하세요**: 덱을 새로 만들어 냈다면 순서 변경이 이동으로 잡히지 않으니, 순서를 일부러 바꿨다면 그 사실을 미리 알려주면 해석이 정확해집니다.
- **두 비교 방식은 섞을 수 없습니다**: 파일 비교와 커밋 비교를 한 번에 요청하면 오류가 납니다. 둘 중 하나를 골라 말해주세요.

---

## 제한사항

- **PPTX 전용**: 워드(`.docx`)·엑셀(`.xlsx`) 비교는 지원하지 않습니다. 해당 포맷을 요청하면 그 사실을 알리고 멈춥니다.
- **읽기 전용**: 차이를 알려줄 뿐, 파일을 수정하거나 두 버전을 병합하지 않습니다.
- **비교 범위는 슬라이드·도형·텍스트 구조**: 애니메이션, 발표자 노트, 미디어(이미지·영상) 내용 자체의 변화는 이 비교에 나타나지 않습니다. 결과에 없는 변경을 "아마 바뀌었을 것"으로 적지 않습니다.
- **hyve 실험 기능 의존**: 문서 읽기 기능이 실험 도메인이라 hyve 설정에서 실험 도메인을 켜야 동작합니다.
- **파일 접근 루트 안에서만**: 비교할 파일이 등록된 접근 루트 밖에 있으면 거부되며, 폴더 추가 안내가 그대로 전달됩니다.
