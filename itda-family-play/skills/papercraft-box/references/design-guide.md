# 설계 가이드

## 1. 마인크래프트 유닛 표 (게임 픽셀 = 유닛, px_per_unit 1)

| 스티브/알렉스/좀비/피그맨/피글린/주민 | 머리 8³, 몸통 [8,12,4], 팔 [4,12,4]×2, 다리 [4,12,4]×2 | | 32 | 팔은 몸통 옆면 맨 위, 다리 2개 = 몸통 바닥 폭 |

## 2. 다른 주제 분해 요령

- **머리 폭을 8유닛**으로 잡고 나머지를 비율로 정합니다. 귀여운 비율(SD)은 머리:몸통 높이 1:1, 사실적 비율은 1:2~1:3.
- **동물(사족)**: 몸통을 `[폭, 높이, 길이]`로 정의해 가로로 긴 상자. 머리는 몸통 앞면 위쪽에, 다리는 바닥 네 모서리 안쪽에 — 다리 폭×2 ≤ 몸통 폭이 되게.
- **자동차**: 차체 [16,5,8] + 캐빈 [8,4,7] + 바퀴 flat(원형 픽셀) ×4 또는 작은 상자 [2,4,4]×4.
- **건물/집**: 벽 상자 [12,8,10] + 지붕은 상자 두 개를 계단식으로, 또는 sheet 2장을 ㅅ자로. 문·창문은 텍스처 `rect`.
- **로봇/괴물/원작 캐릭터**: 눈·입은 `rect` 2~3개면 충분. 특징(뿔·안테나·꼬리·무기)은 `flat` 2장.
- 색은 팔레트 3색 noise가 인쇄에서 "재질감"을 줍니다. 단색 fill만 쓰면 밋밋합니다.

## 3. 페이지 수 예측

전개도 경계상자(mm): 폭 `2(w+d)·u + 2t`, 높이 `(h+2d)·u + 2t`. A4 배치 가능 영역 194 × 265 mm, 부품 간격 6 mm.
- 8³ 머리(u 4.6): 159×122 → 한 페이지에 머리+몸통(122×104) 세로로 들어감.
- [4,12,4] 팔다리(u 4.6): 86×104 → 2×2 로 한 페이지.
- 캐릭터 1개 = 보통 2쪽. 블록 [1,1,1] 38 mm = 164×126 → 2개/쪽.

`python3 papercraft.py plan spec.json` 으로 PDF 없이 배치 결과와 쪽수를 먼저 확인할 수 있습니다.

## 4. 텍스처 방향

전개도에서 `top` 면은 `front` 위에, `bottom` 면은 `front` 아래에 붙어 있으므로:
- `top` 텍스처의 **아래쪽 행**이 앞면 쪽(이마 쪽). 머리카락 앞머리를 그리려면 top의 마지막 행 근처.
- `bottom` 텍스처의 **위쪽 행**이 앞면 쪽.
- 옆면 4개는 모두 위가 위. `right`는 앞에서 봤을 때 캐릭터의 오른쪽(관람자 기준 왼쪽)이 아니라 전개도상 front 오른쪽 = 관람자 기준 **오른쪽** 면입니다. 좌우 비대칭 무늬는 `flip: "h"`로 맞추세요.

## 5. 아이템(검·곡괭이·표지판) — `prism` 설계

마인크래프트 아이템은 상자 조합이 아니라 **16×16 스프라이트를 두께 1픽셀로 압출한 판**이다.
`flat`(두께 없는 판)이 아니라 `prism` 을 쓴다.

- **스프라이트를 계단으로 그린다.** 대각선을 그릴 때 행마다 1칸씩 어긋내되 **열이 겹치게** 한다
  (`..11` / `.11.` 처럼 한 칸 이상 공유). 칸이 모서리에서만 닿으면 접을 수 없어 에러가 난다.
- **칸 크기(px)로 완성 크기가 정해진다.** 16칸 대각 스프라이트를 `rotate: -45` 로 세우면
  세로 길이 ≈ 칸 × 22, 가로 ≈ 칸 × 8. 칸 10mm → 22cm 검(A4 2쪽), 칸 22mm → 48cm 검(타일 6쪽).
- **두께는 1칸이 기본**이다. 두꺼우면 띠가 넓어져 종이를 더 먹고 잘 안 선다. 아이템은 1, 표지판·방패는 1~2.
- **띠 조각 수 = 둘레 ÷ 25cm 남짓.** 계단이 많을수록 둘레가 길다(검 16×16 ≈ 둘레 100칸).
  조각이 8개를 넘으면 칸을 줄이는 편이 조립이 쉽다.
- **`tab_mm` 은 칸의 절반 이하**로. 칸 10mm 면 5mm. 이보다 크면 두 가지가 난다:
  오목한 곳에서 날개가 서로 먹으면 **빌드가 실패**하고(에러), 그 전에 짧은 변의 날개가 **한꺼번에
  생략**된다(실측: 칸 7.5·tab 5 에서 60개 → 8개). 후자는 도안이 멀쩡해 보이므로 스크립트가 경고를
  내고 가능한 최대 `tab_mm`(대략 `min(칸−3.3, (칸−0.3)/1.6)`)을 알려 준다 — 그 경고를 무시하지 마라.
- 색은 3~4가지면 충분하다 — 본체 2색(밝음/어두움) + 테두리·자루. 띠 색은 그 변에 닿은 칸 색을
  자동으로 따라가므로 따로 지정하지 않는다.

`assets/examples/diamond_sword.json` 이 이 설계의 표준형이다.

## 6. 결속 — 부품끼리 걸리게 하기 (활과 화살, #1661 → #1663 재설계)

두 부품이 "완성 장면"에서 서로 닿기만 하고 붙지 않는다면 그것은 도안이 아니라 **배치 그림**이다.
활과 화살이 그랬다 — 조감도는 화살이 손잡이를 지나는 것처럼 그렸지만 실물에는 구멍도 오늬도 없어 따로 놀았다.
결속은 **두 점 고정**이 기본이다: 한 점은 회전을 못 막는다.

> ⚠️ **오판 이력(#1661 → #1663)** — 첫 설계는 "활 손잡이 한 칸을 뚫어 화살대가 관통"이었다. 틀렸다: 활 판(xz)과
> 화살대(x 방향 막대)는 **같은 평면**이라 판의 관통구(y 방향)를 x 방향 막대가 지날 수 없고, 구멍 양옆의 채워진 칸과
> 충돌한다. 게다가 촉(3칸)이 8mm 구멍을 못 지난다. 좌표 포함 관계만 재던 테스트는 이것을 통과시켰고, Codex 적대
> 리뷰가 P0 로 잡았다. 지금 게이트는 **고체 교차 부피 0 + 접촉 실재**를 잰다(`tests/test_bow_geometry.py`).
> 되돌려 읽지 마라 — "구멍에 끼운다"는 판에 **수직**으로 지나는 부품에만 성립한다.

| 결속 | 프리미티브 | 언제 |
|---|---|---|
| 칸 단면 관통 | 상대 `flat` 의 `pixels` 에 `.` 한 칸 | `prism` 대가 판에 **수직**으로 지날 때만(같은 평면이면 불가) |
| **종이 고리** | `slots` 2개(가로 슬릿, 간격 = 상대 두께 + 여유) + 띠 `flat` | 판 **앞면에 붙여 눕힌** 막대·관을 붙잡을 때. 상대를 먼저 놓고 띠를 닫으므로 촉 크기와 무관 |
| 받침 선반 | `flat` 1행 + `tab: bottom`(날개를 접어 판 앞면에 붙임) | 관이 **미끄러져야** 하는 자리(발사용 화살 받침) — 고리는 깃이 못 지난다 |
| 얇은 판 관통 | `slots` (w = 종이 두께 + 0.5) | `flat` 2겹(0.6mm)이 판에 수직으로 지날 때 |
| 끈 매기 | `holes` 2개 + 최상위 `cords` | 활시위·고리·매달기 — 끈은 사용자가 준비, 조감도에만 그린다. 끈이 꺾여 닿는 접점은 `{"at":[x,y,z]}` |
| 끈 걸기(오늬) | 실루엣 자체의 홈 또는 가위집 | **홈은 시위 방향(세로)으로 열려야 한다** — 2D 깃 실루엣의 홈은 화살을 **눕혀야** 세로가 된다 |

**활·화살 표준형** (`assets/examples/bow_arrow.json`, 시위 끈 · `bow_arrow_paper_string.json`, 종이 시위):
- 실제 활의 기하: 시위·활대·화살이 **한 평면**에 있고, 화살은 시위 중앙(오늬)에서 손잡이 옆을 스쳐 앞(+x)으로 나간다.
  마인크래프트 아이콘이 이 배치 그대로다(시위 왼쪽 · 화살 가로).
- 활은 `flat` 2겹, 화살은 `prism`(두께 1칸)을 활 **앞면**(−y)에 **눕혀**(`layout.plane: "xy"`) 놓는다. 눕히는 이유는
  오늬다 — 깃 사이 홈(대 행)이 눕혀야 세로(시위 방향)로 열린다. 화살대 뒷면 = 활 앞면(접촉), 고체 교차 0.
- 손잡이 결속은 **종이 고리**: 손잡이 `G` 칸에 가로 슬릿 2개(`slots` 12×1.5, 화살 두께 위·아래로 1~2mm 여유)를
  두 장 모두 뚫고, 띠(`flat` 50×10)를 뒤 → 위 슬릿 → 화살 위 → 아래 슬릿 → 뒤로 통과시켜 풀칠한다.
- 시위 끈 판: 종이 시위 열을 없애고 양 끝 칸 중심에 `holes`(2.5mm). `cords` 는 구멍 → **오늬 접점** → 구멍 두 선분.
  접점은 **끈 중심선**이므로 고체 표면에서 끈 반지름만큼 떨어뜨린다(대 끝 x − r · 뒤 깃 앞면 y − r · 두께 z 중앙 —
  예제 `[15.5, -0.5, 60]`). 왜 그 모서리인가: 두 구멍이 당기는 장력의 합력은 접점에서 **+y(활 쪽)** 뿐이라 시위는 홈
  중앙에 머물지 않고 뒤로 밀려 **뒤쪽 깃 앞면(y=0)** 에 눌린다. 그 벽이 y 를 받치고 대 끝면이 x 위치를 정한다 —
  x 방향 유지력은 없으므로 `assembly` 에 "풀 한 점" 을 권한다(Codex R2 N01·N02). 활 끝 구멍 x = 대 끝 x 로 맞춘다.
- 종이 시위 판: 시위 열을 그대로 두고 고리만. 뒤쪽 깃이 종이 시위 열과 겹치지 않게 화살을 1칸 뒤로 물린다.
  화살은 고리로만 고정되고 시위에는 걸리지 않는다(문서에 그렇게 쓴다).
- 활대 2겹 사이에 나무 꼬치를 넣으라고 `assembly` 에 쓴다(시위 장력).

**하지 않는 것**: 결속 없이 `assembly` 에 "걸쳐 놓으면 완성"이라 쓰는 것. 조감도가 그럴듯할수록 실물의 공백을 가린다.
**미실측**: 마찰·장력·찢김은 인쇄·조립 실측 전이다 — "저절로 고정" 같은 확정형 서술을 쓰지 않는다(#1663 F15).

## 7. 발사용 활 — 강체 활 + 고무줄 + 말아 만든 화살대 (#1662 → #1663 재설계)

이 스케일(A4 2겹)의 종이 활은 휘어서 탄성을 내지 못한다. 아동 종이활의 원리는 "활은 강체, 탄성은 고무줄"이다.
이 분해를 지키면 전개도 네 종류(활 `flat` · 화살대 `tube` · 깃 `flat` · 받침 `flat`)로 끝난다.
표준형 `assets/examples/bow_arrow_shooter.json`(24cm).

> ⚠️ **오판 이력(#1662 → #1663)** — 첫 설계는 화살을 활 평면에 **수직**(`axis: "y"`)으로 두고 손잡이 변에 홈을 팠다.
> 그러면 꼬리가 시위에서 50mm 떨어진다(Codex P1). 화살은 §6 과 같이 **활 평면 안에서 앞(+x)** 으로 놓인다.

| 축 | 설계 | 이유 |
|---|---|---|
| 활 크기 | 24cm(unit 16 · 15칸) — A4 한 장 | 사거리는 시위 장력이 정하지 활 길이가 정하지 않는다. 더 크면 타일 인쇄 + 2겹 뒤틀림 |
| 활 강성 | `flat` 2겹 사이에 나무젓가락 2개(또는 24cm 로 자른 꼬치)를 활대 길이로, 끝 구멍 옆까지 | 고무줄 장력을 2겹 종이가 못 버틴다 — `assembly` 에 반드시 쓴다 |
| 시위 | 양 끝 `holes`(3.5mm) + `cords`(구멍 → 오늬 접점 → 구멍). 늘이지 않은 길이 = 구멍 사이 거리 − 2~3cm 인 고무줄 | 팽팽해야 튕긴다. 낚싯줄은 안 튕긴다(전시용 §6 과 다른 점) |
| 화살 받침 | 활 **앞면** 손잡이에 **받침 선반**(`flat` 1행 + `tab: bottom` 을 90° 접어 붙임) | 화살은 활 앞면에 붙어 앞으로 나가므로 관 **아래**를 받친다. 고리는 깃이 못 지나 발사용엔 쓰지 않는다 |
| 화살대 | `tube` 지름 6 · 길이 = 활 길이 × 0.7 (24cm 활 → 17cm) · 3겹 · **일반 복사지** | 짧으면 당길 거리가 없고 길면 처진다. 마분지는 6mm 로 말리지 않는다. 심(꼬치)은 뽑아 가볍게 |
| 깃 | `flat` 2장(5mm 칸, `tab: bottom`) — 관 **위**(`plane: xz`)와 관 **앞**(`plane: xy`), 꼬리 1cm 앞 | 활 쪽(뒤)·아래에는 깃을 두지 않는다 — 활·받침에 걸린다 |
| 오늬 | `tube` 의 `nock_mm`(점-선) — 말고 난 뒤 **세로로** 가위집 | 시위가 세로선이라 홈도 세로여야 걸린다. 절개 위치는 말린 뒤에야 정해져 인쇄로 못 만든다 |
| 촉 | **지우개 조각·스펀지 끼우기(안내문만)** — 마스터 결정 | 종이 원뿔도 딱딱하다. 도안에 촉이 없는 것이 설계다. 안전 보장은 아니다 — 이탈·충격은 미검증 |

- **안전 문구는 `assembly` 필수**: 사람·동물·얼굴 조준 금지, 실내 2m 이내 표적, 어린이는 어른과. 촉을 딱딱하게 만들지 말 것.
- `layout`: 화살대 `axis: "x"`, 뒷면 = 활 앞면(y 0), 꼬리 x = 활 끝 구멍 x(시위 x). `cords` 접점 = **가위집 바닥**(꼬리 x +
  `nock_mm`, 관 중심 y·z) — 세로 가위집의 xz 벽이 y 를 받치고 바닥이 x 를 받친다. `nock_mm` 은 0 이면 안 된다(게이트가 잰다).
  받침은 관 바닥 바로 아래 · 손잡이 x 안. 깃은 관에 닿고 활에는 닿지 않게. 조감도에서 대가 손잡이 앞을 지나고
  시위가 꼬리에서 3mm 꺾이면 배치가 맞다 — `tests/test_bow_geometry.py` 가 교차 0·접촉·발사 경로(깃이 받침 위)를 잰다.
- **미실측**: 사거리·정확도·관의 강성·구멍 찢김·촉 유지력은 인쇄·조립·발사 실측 전이다. 문서와 `assembly` 에 그렇게 쓴다.
  실측되면 여기에 기록한다.

## 8. 기존 PDF 검토 체크리스트

`python3 papercraft.py verify file.pdf` 후 수동 확인:
0. `prism` 부품이면: 앞면·뒷면·띠가 모두 있는지, 띠 칸 길이 합이 실루엣 둘레와 맞는지, 접는 선이
   두 종류(점선/점-선)로 구분돼 있는지. 띠 조각 끝마다 회색 '이음' 자리가 있는지(마지막 조각 제외).
1. 부품마다 회색 날개 7개(닫힌 십자 전개도 기준; 한 면을 뚫은 `open` 부품은 8개). 6개면 한 모서리를 못 붙이고, 필요 이상이면 겹쳐서 두꺼워짐.
2. 붙는 면끼리 치수 일치(다리 2개 폭 합 = 몸통 바닥, 팔 깊이 = 몸통 깊이, 머리 바닥 ≥ 몸통 윗면).
3. 표기 높이 = 머리 h + 몸통 h + 다리 h 실측 합 (A4 595×842 pt, 1 pt = 0.353 mm).
4. 날개 폭 ≥ 5 mm, 가는 기둥은 4.5 mm 이상.
5. 부품 경계가 A4 여백 8 mm 안, 부품 간 간격 ≥ 3 mm(가위 들어갈 자리).
6. 다리 4개가 몸통보다 넓은 구조(크리퍼)는 "다리끼리 먼저 붙이기" 지시가 있는지.
7. 접기 점선/자르기 실선 구분, 회색 날개 범례, 종이 무게 안내가 있는지.
8. **어두운 면 위의 접는 선이 보이는지.** 스크립트가 배경 밝기로 선 색을 고르지만(어두우면 밝은 점선), 이전 버전으로 만든 도안은 고정 회색이라 검은 몹에서 선이 묻힌다 — 그런 PDF 는 스펙이 있으면 재빌드한다.
9. **서로 닿는 부품이 실제로 결속되는지.** `assembly` 가 "걸쳐 놓는다"·"올려 둔다"로 끝나면 결속이 없는 것이다(§6). 구멍·슬릿·끈 중 무엇이 잡아 주는지 도안에서 찾는다.

pymupdf로 면 치수 뽑기:

for x in p.get_drawings():
    r = x["rect"]; f = x.get("fill")
    if f and r.width > 30 and r.height > 30: print(round(r.x0/2.835,1), round(r.y0/2.835,1), round(r.width/2.835,1), round(r.height/2.835,1), f)
