# 스펙 JSON 형식

## 최상위 키

| 키 | 필수 | 설명 |
|---|---|---|
| `title` | ✓ | 영문 제목(헤더·푸터) |
| `title_ko` | | 한글 제목 |
| `difficulty` | | "입문" / "쉬운" / "보통" / "어려운" — 부제에 표시 |
| `subtitle` | | 부제를 직접 쓰고 싶을 때(자동 문구 대체) |
| `unit_mm` **또는** `scale` | ✓ | `unit_mm`: 1유닛 mm. `scale: {"target_height_mm": 150, "height_units": 32}` → unit = 150/32 |
| `height_units` | | `unit_mm`를 직접 줄 때 완성 높이 표기용 (세로로 쌓이는 유닛 합) |
| `fit` | | `true`면 가장 넓은 부품이 A4에 들어가도록 unit을 자동 축소 |
| `tab_mm` | | 풀 날개 폭 기본값 (기본 6). 부품별로 덮어쓸 수 있음 |
| `px_per_unit` | | 1유닛당 텍스처 픽셀 수 (기본 1). 마인크래프트 블록은 16, 캐릭터는 1 |
| `palettes` | | `{이름: ["#hex", ...]}` — noise 바탕에 쓰는 색 묶음 |
| `textures` | | `{이름: 텍스처객체}` — 면에서 이름으로 참조 |
| `parts` | ✓ | 부품 배열 (아래) |
| `assembly` | | 조립 안내 문장 배열. 첫 줄은 "조립 순서: A → B → C" 형식 권장. 종이 요령은 자동 추가됨 |
| `tile` | | A4 를 넘는 부품을 여러 장으로 쪼개 인쇄(기본 true). `false` 면 종전대로 에러. 장수는 인쇄 영역(194×275mm)이 정하고 **그 안에서 균등 분배**된다 — 겹침 10mm 를 유지하며 부품을 정확히 덮는다(#1679) |
| `layout` | | 조감도용 배치 `[{"id", "at_u": [x,y,z], "at": [x,y,z], "i"}]` — `at_u` 는 유닛, `at` 은 mm(둘 다 주면 합산). x 오른쪽·y 뒤쪽·z 위, 부품의 왼쪽·앞·바닥 모서리. `i` 는 `count>1` 부품의 인덱스(0부터, `seed_shift` 반영). `flat`·`prism` 은 `plane: "xz"`(기본, 정면 판) / `"yz"`(옆을 보는 판) / `"xy"`(눕힌 판 — 0행이 앞, 두께가 위; 활 앞에 눕힌 화살·수평 깃), `tube` 는 `axis: "x"|"y"|"z"`(길이 방향, 기본 x). 생략 시 부품을 바닥에 나란히 |
| `cords` | | 끈(활시위·고리 줄) `[{"from": {"id", "px": [col,row], "i"}, "to": {"at": [x,y,z]}, "color": "#EEEEEE", "d_mm": 1}]`. 끝점은 **그 `flat` 부품의 `holes` 좌표와 정확히 일치하는 구멍**이거나 `{"at": [x,y,z]}` **자유점**(mm — 오늬처럼 끈이 꺾여 닿는 접점)이며, 적어도 한쪽은 구멍이어야 한다. `i` 는 `0 ≤ i < count` 정수, `d_mm` 은 양수, 색은 `#RRGGBB`/`#RGB`. 위반은 `plan`/`build` 모두 에러(조감도의 끈이 도안에 없는 구멍을 가리키면 안 된다). PDF 에는 그리지 않고(재료는 사용자 준비) 조감도에 굵기 `d_mm` 의 가는 기둥으로 렌더 + 안내문 자동 삽입 |

## 부품 (`parts[]`)

공통: `id`, `label`(1개) 또는 `labels`(count개), `count`(기본 1), `tab_mm`(덮어쓰기). 번호는 자동으로 앞에 붙습니다("3. 왼팔").

### `type: "box"` (기본) — 십자 전개도
```json
{"id": "head", "label": "머리", "size": [8, 8, 8],
 "faces": {"front": "face", "right": "side", "back": "back", "left": "side", "top": "hair", "bottom": "skin"},
 "seed_shift": true}
```
- `size`: `[폭 w, 높이 h, 깊이 d]` 유닛. 전개도 폭 = `2(w+d)·unit + 2·tab`, 높이 = `(h+2d)·unit + 2·tab`.
- `faces`: 6면. 축약 `sides`(front/right/back/left), `all`(6면 전부). 개별 키가 우선.
- 면 크기: front/back = w×h, right/left = d×h, top/bottom = w×d (픽셀 = 유닛×px_per_unit).
- 전개도 배치: `top` 이 `front` 위, `bottom` 이 `front` 아래, 옆면은 front→right→back→left 순으로 오른쪽으로.
- `seed_shift`: count>1 일 때 i번째 부품의 noise seed를 +1000·i (무늬가 서로 다르게).
- `open`: `"bottom"` 또는 `"top"` — 그 면을 만들지 않고 개구부 4변에 안쪽 접는 풀 날개를 둠. 다른 부품에 눌러 붙이는 결합면에 사용(머리 바닥·다리 윗면). 해당 면 텍스처는 생략 가능. 날개 수는 8개가 됨.
- `close`: `"glue"`(기본) 또는 `"tuck"` — top 면의 바깥쪽 날개를 풀 없이 끼우는 긴 혀(높이의 0.6배, 최대 14 mm)로, 양옆은 흰 먼지날개. 마지막에 닫는 뚜껑에 사용. `open: "top"`이면 무시.

### `type: "flat"` — 평면 부품 (검, 귀, 꼬리, 안테나, 팻말)
```json
{"id": "sword", "type": "flat", "labels": ["금검(앞)", "금검(뒤)"], "count": 2,
 "px_mm": 2.6, "tab": "bottom", "tab_mm": 5,
 "pixels": ["..11..", ".1111.", "222222", "..33.."],
 "key": {"1": "#FAD440", "2": "#D9A626", "3": "#734D26"}}
```
- `pixels`: 문자열 배열. `.` 은 빈칸(잘라냄). 외곽선은 채워진 픽셀의 노출 변만 자동으로 그려짐.
- `tab`: 날개를 붙일 변 (`top|bottom|left|right|없음`). 그 변에서 가장 긴 채워진 구간에 날개가 붙음.
- 보통 `count: 2` 로 앞/뒤를 뽑아 등 맞대어 붙임(날개는 한 장만 남김).
- **결속 절개** (#1661 — 부품끼리 걸거나 끈을 매는 자리):
  - `holes: [{"at_px": [col, row], "d_mm": 2.5}]` — 펀치·송곳 구멍. 실선 원 + 조준 십자로 인쇄. 칸 좌표는 소수 허용
    (칸 (r,c) 의 중심 = `[c+0.5, r+0.5]`), **원 전체가 채워진 픽셀 안**에 들어야 한다 — 빈 칸·종이 밖 사각형과의 **정확 교차**로
    판정하므로 모서리 사이로 무는 원도 에러다(뚫을 종이가 없다).
  - `slots: [{"at_px": [col, row], "w_mm": 12, "h_mm": 1.5}]` — 직사각 절개(흰 채움 + 절단선). 종이 고리 띠가 지나는 가로 슬릿,
    얇은 `flat` 상대를 끼우는 슬릿, 변에 걸친 홈. 중심은 채워진 픽셀 안이어야 하고, **그림은 실루엣 안에서만** 그린다(변 밖
    부분은 잘린다 — 부품 밖·이웃 부품 위로 나가지 않는다). 구멍(`holes`) 둘레 1mm 안을 침범하면 에러.
  - 칸 단면이 판에 **수직으로** 지나는 구멍은 `pixels` 의 `.` 한 칸으로 뚫는다. 같은 평면에 눕힌 막대는 구멍을 지날 수 없다 —
    **종이 고리**(슬릿 2개 + 띠)로 붙잡는다(`design-guide.md` §6).
  - 절개가 하나라도 있으면 "두 장을 맞대기 전에 각 장에 따로 뚫으라"는 안내가 자동으로 실린다.

### `type: "prism"` — 픽셀 실루엣을 두께 방향으로 압출 (검·곡괭이·표지판·두꺼운 아이콘)
```json
{"id": "sword", "type": "prism", "label": "다이아몬드 검",
 "px_u": 1, "thickness_u": 1, "rotate": -45, "tab_mm": 5,
 "band_overlap_mm": 10, "band_ease_mm": 0.5,
 "pixels": ["..11", ".121", "3333"],
 "key": {"1": "#4FD8DE", "2": "#B6F2F5", "3": "#3B3B3B"}}
```
`flat` 이 앞뒤 2장을 맞대는 **두께 없는 판**이라면, `prism` 은 옆면이 있는 **입체**다.
한 부품에서 세 종류가 나온다:

| 산출 | 내용 |
|---|---|
| 앞면 1장 | 실루엣 + 외곽 변마다 풀 날개(띠를 붙이는 자리) |
| 뒷면 1장 | 좌우 미러, 날개 없음 |
| 옆면 띠 N조각 | 폭 = 두께, 길이 = 실루엣 둘레. 칸마다 색·톱니, 코너마다 접힘선 |

- `pixels` / `key`: `flat` 과 같다. `.` 은 빈칸.
- 칸 크기: `px_mm`(직접) 또는 `px_u` × `unit_mm`(기본 1). 두께: `thickness_mm` 또는 `thickness_u` × 칸 크기(기본 1).
- `rotate`: 앞뒤 면을 돌려 배치(도 단위). 대각선 스프라이트(검·곡괭이)를 `-45` 로 세우면 똑바로 서고 A4 도 덜 먹는다. **띠는 돌리지 않는다**(직사각형이 효율적). 3D 조감도와도 무관하다 — 완성품은 스프라이트가 놓인 방향 그대로다.
- `tab_mm`: 앞면 날개와 띠 톱니의 깊이. 오목 코너 쪽 끝만 이만큼 물린다.
- `band_overlap_mm`(기본 10): 띠 조각을 이어 붙일 때 겹치는 길이.
- `band_ease_mm`(**기본 0**): 종이 두께 때문에 띠가 실제로 감싸야 하는 경로가 길어지는 몫. **폐곡선당 한 번**
  마지막 자유단에 더한다 — 닫힌 실루엣을 d 만큼 바깥으로 오프셋하면 둘레는 `2πd` 늘고, 그 값은 코너가
  몇 개든 총 회전각이 360°(볼록−오목=4)라 상수다. 조각 수는 A4 배치의 산물이라 여기에 곱하지 않는다.
  기본값이 0 인 이유: 실제 계수는 종이 caliper·접힘반경·접착층에 달려 **인쇄·조립 실측으로만** 정해진다(#1654).
- **접는 선 두 종류**: 볼록 코너 = 점선(산접기), 오목 코너 = 점-선 무늬(골접기). 같은 방향으로 이어지는 변은 접힘선 없이 합쳐진다.
- **선 색은 배경 밝기를 따른다**(모든 부품 공통): 어두운 면 위에서는 밝은 점선. 면 안에서 밝기가 갈리면 구간을 나누되 같은 색 구간은 병합한다.
- **접을 수 없는 실루엣은 에러다**: 조각이 떨어져 있음(부품을 나눠라) · 안에 구멍이 있음(v1 미지원) · 칸이 모서리에서만 닿음(그 자리를 채워라).
- 날개가 면을 먹거나 서로 겹치면 PDF 를 만들지 않고 실패한다 — `tab_mm` 을 줄이거나 칸을 키운다.

### `type: "sheet"` — 한 면짜리 시트 (포털, 창문, 바닥판, 배경)
```json
{"id": "portal", "type": "sheet", "label": "포털 시트", "size": [2, 3], "texture": "portal",
 "tabs": ["left", "right", "top", "bottom"]}
```
- `size`: `[폭, 높이]` 유닛. `tabs`: 날개를 붙일 변 목록.

### `type: "tube"` — 종이를 말아 만드는 관 (화살대, 깃대, 가는 기둥) (#1662)
```json
{"id": "shaft", "type": "tube", "label": "화살대(말기)",
 "length_mm": 170, "diameter_mm": 6, "turns": 3, "tab_mm": 8, "nock_mm": 6, "color": "#C8A165"}
```
- 산출은 **띠 한 장**: 가로 = `length_mm`, 세로 = `π·diameter_mm·turns + tab_mm`. 위 변에 꼬치(안지름 = `diameter_mm`)를 대고
  아래로 말아 마지막 회색 '풀' 띠로 마감한다. 한 바퀴마다 확인 점선, 왼쪽 = 머리 · 오른쪽 = 꼬리.
- `turns`(기본 3, **정수** ≥ 1): 겹 수. 80g 일반지 3겹을 화살대 기준으로 삼는다(강성은 미실측 — 처지면 4겹). 겹이 쌓이며 늘어나는
  둘레(종이 두께 ≈ +0.6mm/3겹)는 풀 띠가 삼킨다.
- `tab_mm`(기본 8, 양수): 풀 띠. **최상위 `tab_mm` 을 상속하지 않는다** — 날개 폭이 아니라 마지막 바퀴의 겹침 여유라 다른 축이다.
- `nock_mm`(기본 6, 0 이면 없음, `< length_mm/2`): 꼬리 끝에서 이 거리에 점-선 — 말고 난 뒤 그 선까지 **세로로**(시위 방향)
  가위집을 내면 시위가 걸리는 오늬가 된다.
- 모든 치수는 유한한 수여야 한다(NaN·inf·음수 풀 띠·소수 겹 수는 에러). 안내 문구는 띠 안에 클립되고, 짧은 관(길이 < 70mm)에는
  넣지 않는다.
- 조감도는 지름 `diameter_mm` 의 사각 단면 막대로 근사(`layout` 의 `axis` 가 길이 방향).
- 관에 붙는 깃·날개는 `flat` + `tab`(날개가 관을 감싸 붙는다)으로 따로 만들고, 조감도에서는 관의 `axis` 와 깃이 뻗는 방향에
  맞는 평면을 고른다 — `axis: "x"` 관의 위 깃은 `xz`, 앞 깃은 `xy`(발사용 예제), `axis: "y"` 관이면 `yz`/`xy`.
- `tests/_geom.py` 는 render3d 의 기저 변환을 **재사용**하므로 좌표 변환 자체의 독립 검증이 아니다 — 변환은 `test_tube.py` 의
  기대값 테스트가 따로 고정한다.
- 길이가 194mm 를 넘으면 타일 인쇄로 쪼개진다 — 이어 붙인 뒤 말아야 하므로 가능하면 길이를 A4 안에 둔다.

## 텍스처 객체

문자열이면: 팔레트 이름 → noise, `#hex` → 단색, textures 이름 → 참조.

객체 키(위→아래 순서로 적용):

| 키 | 예 | 의미 |
|---|---|---|
| `fill` | `"#27B5B5"` | 단색 바탕 |
| `noise` + `seed` | `"skin", 1` | 팔레트에서 무작위 바탕(결정적) |
| `pixels` + `key` | `["ab", "ba"], {"a":"#..","b":"#.."}` | 정확한 픽셀 그림. 크기가 면 크기와 같아야 함 |
| `rows` | `[[0, 1, "hair"], [11, 11, "#595959"]]` | r0~r1 행 전체를 색/팔레트로 |
| `rect` | `[[3, 2, 6, 5, "#1E2A38"]]` | r0,c0 ~ r1,c1 사각형(끝 포함) |
| `paint` | `[[4, 1, "#FFFFFF"]]` | 픽셀 하나 |
| `flip` | `"h"` / `"v"` | 좌우/상하 뒤집기 (대칭 부품에) |

좌표는 `[행, 열]`, 0부터, 행은 위에서 아래. 면 밖 좌표는 무시됩니다.

## 조감도 (`layout`)

`render` 는 `layout` 의 자리에 부품을 놓고 등각 투영으로 그린다. 면의 픽셀은 `build` 와 같은 `build_grid` 산출이라 인쇄면과 같다.
- `box`: 6면 그대로(`open` 면은 비움). `flat`: 앞뒤 2장 맞대기 두께 0.6mm 판, `.` 픽셀은 뚫림. `prism`: 같은 판이되 두께가 `thickness_*`(도면의 `rotate` 는 배치용이라 3D 에 반영하지 않는다). `sheet`: xz 평면에 세운 한 장.
- `cords` 는 `flat` 부품의 구멍 좌표(종이 두께 가운데)를 잇는 가는 사각기둥. `holes`/`slots` 자체는 작아서 렌더하지 않는다.
- `tube` 는 사각 단면 막대(`axis` 방향으로 `length_mm`), `flat`·`prism` 은 `plane` 에 따라 xz(정면)·yz(옆)에 서거나 xy 로 눕는다.
- 조감도는 painter 정렬(면 평균 깊이)이라 긴 끈·관이 다른 부품과 교차하는 자리에서 가림이 틀릴 수 있다 — **접촉·충돌 판정의
  대체물이 아니다**. 그 판정은 배치 수치로 한다(`tests/_geom.py` 의 고체 AABB 교차).
- 렌더하지 않는 것: 풀 날개·종이 두께·접힘 자국·원근. 명암은 면 법선으로만.
- 판별: 조감도에서 부품이 서로 파고들거나 떠 있으면 `layout` 또는 `assembly` 가 틀린 것이다(둘은 같은 사실을 말해야 한다).

## CLI

```
python3 papercraft.py build  spec.json out.pdf [--preview DIR] [--dpi 60] [--render]   # 생성 + 자동 verify (+ 조감도 쪽 첨부)
python3 papercraft.py verify out.pdf                                        # 기존 PDF 기하 검증(조감도 쪽은 검사 제외)
python3 papercraft.py plan   spec.json                                      # 배치·크기만 미리 계산
python3 papercraft.py render spec.json out.png [--yaw -35] [--pitch 30] [--scale 8]   # 조감도 PNG 한 장
```
`build` 는 폭 초과 시 "가능한 최대 unit_mm" 를 알려주고 종료합니다. `verify` 는 회색(0.87) 사각형을 날개로 인식하므로 텍스처에 `#DDDDDD` 계열 회색은 피하세요.
